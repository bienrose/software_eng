# AIMS database schema

This folder contains the initial relational schema for **MySQL 8.0.16 or later**. The existing Next.js project does not yet include a database driver, ORM, or migration framework, so this is a database design artifact; it is not wired into the app yet.

## Files

- `schema.sql` creates the core tables, constraints, indexes, and triggers.

## Core and adaptive data model

The core model keeps stable inventory facts in columns: category, item code, name, unit, on-hand quantity, and reorder level. Inventory movement history is recorded in `inventory_transactions`; a trigger updates on-hand quantity, rejects stock-outs that would make it negative, and records the resulting balance. Transaction rows are append-only; record a compensating movement to correct an earlier entry.

Adaptive fields are stored as versioned metadata:

1. Create an `inventory_categories` row.
2. Create an `inventory_schema_versions` draft for that category.
3. Store each generated field in `inventory_schema_fields` with a key, label, type, required flag, options, and validation rules.
4. Review the generated field definitions, then publish the version by setting its status to `active` and `published_at`. When replacing an active version, retire the old version and activate the new one in the same transaction.
5. Store values for those fields in each item's `custom_attributes` JSON object, keyed by `field_key`.

For example, a medical-supplies item could use:

```json
{
  "expiration_date": "2027-06-30",
  "batch_number": "MED-2026-001",
  "supplier": "Supplier A"
}
```

The item retains the schema version that defines its custom attributes. To change a category's fields, create and validate a new draft version; do not rewrite a published version. The database stores declarative field metadata instead of running SQL generated from user text. The application should validate `custom_attributes` against the item's schema version before saving.

## XGBoost records

`demand_predictions` supports either classification (`low`, `moderate`, or `high` demand) or regression (a predicted quantity). The selected mode, target definition, thresholds, features, and evaluation metrics still need to be finalized from the study's actual dataset and approved methodology.

## Apply

Create a new MySQL database using `utf8mb4`, then apply `schema.sql` once using the MySQL command-line client or a SQL editor that supports the `DELIMITER` directive. UUID values are generated by the application and stored as `CHAR(36)`. The SQL is an initial schema, not a repeatable migration; use a migration framework before evolving it in a shared or production database.

MySQL runs DDL statements with implicit commits, so if an error interrupts first-time setup, inspect which objects were created before rerunning the script.

## Design assumptions

- The eventual database is MySQL 8.0.16+; the project previously had no configured database engine.
- One user account has one application role (`admin`, `inventory_manager`, `staff`, or `viewer`).
- Each item belongs to one category and one schema version.
- Existing item fields stay stable, while category-specific fields are stored in JSON and defined by schema metadata.
- Schema generation produces drafts that must be reviewed before activation.
- The application generates UUID v4 IDs and validates custom values against the item's schema version.
